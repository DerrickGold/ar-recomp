# Verified configuration materialization — 2026-09-09

This milestone adds an actual write workflow: `snesbuild materialize` and
`v2regen materialize`. It does not change inference thresholds, decoder/emitter
policy, generated-region semantics, runtime code, or game configuration.

## Scope of the equivalence gate

Both regenerations consume the same persisted proven-analysis database. The
only difference is whether redundant authored declarations remain in cfg.
Every generated file and `funcs.h` must match byte for byte before publication.
This is **not** a default-versus-proven-analysis runtime comparison.

The existing return/alias/known-bit reports remain report-only. No conditional
fact was promoted to make the write workflow succeed.

All three passed complete generated-file/header equality. ActRaiser's removed
funcs comprise 136 exact continuations and two directly rediscovered routines.
Its bank configs go from 1,748 to 1,610 `func` lines, 84 to 71 RTS declarations,
and three to zero indirect declarations. The remaining 71 RTS declarations do
not cross the exact-match persistence gate; compatible guards are not deleted.

The other games have no eligible authored declarations in these frozen input
snapshots. Battletoads has two non-template-free routine facts; MMPR has zero
persisted facts. Neither result licenses removing named roots or converting
open findings into facts. A zero-fact DB still explicitly selects the existing
proven-analysis generation mode, as documented in `ANALYSIS.md`.

Existing generated diagnostics are unchanged: ActRaiser has zero unresolved
indirect sites and six stub markers; Battletoads has 17/66; MMPR has 29/349.
These are emitted-source counts, not evidence that a diagnostic executes or
that runtime coverage is complete. The checks used `--allow-stubs` and did not
waive the byte-equality gate.
